## 1. 结论摘要

**可以进入全文结构化处理阶段。** 两份官方 PDF 都是**原生文本 PDF（非扫描件）**，159 / 144 页全部含可提取文本层，无空白页、无替换字符（U+FFFD）、无 OCR 需求；内置书签、印刷目录、印刷页码三者互相自洽。

- 特殊字体页已单独抽样：2026 物理 P70（SimHei + TimesNewRomanPSMT，流程图页）、P85（OpenSans）；2027 物理 P68（SimHei + TimesNewRomanPSMT，流程图页）、P83（OpenSans，科技核心位姿表）。这些页面的正文文字提取正常，问题在于图形语义（见 6.7 / 6.8）。

### 4.4 表格提取质量

抽样页：2026 物理 P94/P95/P96/P97/P103/P120/P130，2027 物理 P93/P94/P83/P21/P117/P95。同时用 PyMuPDF `find_tables()` 与 pdfplumber `find_tables()` 比对（原始对照见 `ai_workplace\audit\tables\table_compare.txt`）。

| 页码 | PyMuPDF | pdfplumber | 判定 |
|---|---|---|---|
| 2026 P94 | 2 表（2×6 / 13×16，空 67%） | 2 表（1×6 / 13×16，空 70%） | pdfplumber **丢最后一列** 14/18/22 等值 |
| 2026 P95 | 2 表（9×14 / 11×10，空 63%/68%） | 2 表（9×14 / 11×10，空 67%/78%） | pdfplumber **整列丢失**（底盘功率上限 60/65/…/100 全空） |
| 2026 P96 | 2 表（11×12 / 9×12） | 2 表（11×12 / 9×12） | 均把合并单元格展开，pdfplumber 空单元格更多 |
| 2026 P130 | 3 表 | 被拆成 4 个 1×2 且空白 | pdfplumber 结构误判 |
| 2027 P117 | 4 个 1×2 表 | 4 个 1×2 但**100% 空白** | pdfplumber 丢数据 |

- 两份文档的表都大量使用**纵向合并单元格**（如"发射机构类型/近战优先/功率优先/血量优先"跨多行）。两个引擎都会把合并区域展开为空格网格，**抽样 13 页的空单元格率为 63%–85%**，因此 "空单元格多" 不等于识别失败，但**行/列归属必须由后续归并逻辑重建**。
- **结论：表格提取以 PyMuPDF `find_tables()` 为主**，pdfplumber 仅用于交叉校验，不得作为唯一来源。
- 图 5-14 那一类表的原始渲染与提取结果已人工对照（`ai_workplace\audit\img\26_p095.png`），可见内容无丢失，丢失的只是合并语义。

### 4.5 文本顺序

对全部 159 + 144 页做了两种顺序的对比：默认 `get_text("text")`（内容流顺序）与 `get_text("text", sort=True)`（几何顺序），剔除页眉/页脚带后按词序逐页比较。

- **普通正文页**：2026 的 64 个正文页中 **56 页两种顺序完全一致**；2027 的 56 页中 **46 页完全一致**。不一致的页面（2026 P76/P101/P105/P107/P111/P112/P126/P149，2027 P63/P74/P75/P98/P101/P103/P108/P109/P118/P139）全部是**含公式或多文本框**的页面，需在结构化阶段逐页确认取序。抽查 2026 P16/P17 的差值为页脚块位置差异，**正文段落本身未发现错序**。
- **表格页 / 图形标注页**：2026 的 63 个表页、2027 的 57 个表页中，各自只有 **7 页**两种顺序一致。原因是默认输出按"每个定位文本块一行"输出，把一行视觉表格拆成多行；而 `sort=True` 会把同一基线的多个单元格合并成一行并用空格连接，在修改日志表上甚至出现**相邻列直接粘连**（例：`…补充多处描述2026.04.30    V1.4.2`）。也就是说：**表格内容在任一纯文本顺序下都会失去行列归属**。
- 因此：**纯文本导出不足以承载表格**，下一阶段必须走"几何 + 表格检测"的结构化路径，而不是 `get_text("text")` 一把梭。

## 6. 异常清单（含页码）

### 6.1 【严重】2026 封面文本层完全乱码 — 2026 物理 P1
提取结果（前 120 字符）：
```
72\x0f2\x0f0  /  嫱饋錞ⴭ䣆⫊  /  儬榻㛻䄳飃篒㵒䤻颂  /  3PCP.BTUFS\x01篯㡧⚢  /
\x13\x1126\x01䇗\x018 僖  /  瑭◅ⶇ◑㷐⪓㎁㛻㰣榟儬\ue628☕㛻颂
```
渲染图（`img\26_p001.png`）实际显示为：`V2.2.0` / `第二十五届全国大学生机器人大赛` / `ROBOMASTER 2026` / `机甲大师超级对抗赛` / `比赛规则手册` / `RoboMaster 组委会 编制` / `2026 年 8 月 发布`。

- **原因**：该页引用了 5 个 Identity-H CID 字体但缺少 ToUnicode CMap，其中一个字体声明为 `GBK-EUC-H` 编码却按 Identity-H 解析，编码错配。
- **影响**：不能从 2026 封面读取版本号、标题与发布日期。
- **处理**：封面文字**一律不进入结构化结果**；版本号取 `修改日志`（物理 P3）与文件名。封面如需引用，按图片处理。

### 6.2 【严重】2027 封面文本层缺失大半 — 2027 物理 P1
该页文本层只有 23 个字符：`六 / V\uf6b2.0.0 / \uf6b3\uf6b126 年 10 月 发布`。

- 渲染图上存在的 `第二十六届全国大学生机器人大赛`、`ROBOMASTER`、`机甲大师超级对抗赛`、`比赛规则手册`、`RoboMaster 组委会 编制` 在文本层中**完全不存在**（以矢量轮廓呈现）；残存字符中 `V<U+F6B2>.0.0`、`<U+F6B3><U+F6B1>26 年` 含 3 个私用区码位。
- **处理**：同 6.1，封面不作为文本来源。

### 6.3 【中】Wingdings 项目符号落在私用区
`U+F06C`（一级项目符号）出现 2026 共 435 次 / 2027 共 356 次，覆盖 70 / 64 页；`U+F0D8`（二级项目符号）出现 33 / 32 次。2026 封面另有 `U+E628`，2027 封面另有 `U+F6B1/F6B2/F6B3`。

- 这不是乱码，是 Wingdings 的 Unicode 映射缺失。**处理**：结构化时把 `U+F06C` 规范化为 `•`，`U+F0D8` 规范化为 `◦`，或在项目符号上下文中丢弃；**不得**把它当成规则正文内容参与差异比对。
- 出现页示例：2026 物理 P2、P3、P4、P5、P17、P19、P77；2027 物理 P2、P15、P17、P76。

### 6.4 【中】表格合并单元格被展开为空网格
2026 物理 P94–P97、P103、P120、P130；2027 物理 P93–P95、P117、P21 等 60 余页。抽样 13 页的空单元格率为 63%–85%。

- **处理**：用 `find_tables()` 拿到网格后，按"空单元格与其左/上非空单元格同属一个合并区"的规则重建 rowspan/colspan，再回填；对 `等级 1–10` 这类纵向递增表，必须逐表核对列归属。

### 6.5 【中】pdfplumber 在部分表格上丢数据
2026 物理 P94（末列 14/18/22/24 丢失）、P95（"底盘功率上限（W）"整列 60–100 丢失）、P130（1×6 表被拆坏）；2027 物理 P117（4 个表 100% 空白）。

- **处理**：表格只用 PyMuPDF 结果；pdfplumber 若使用，必须**逐表与渲染图比对**后才能采信。

### 6.6 【中】修改日志表提取顺序错位 — 2026 物理 P3–P4、2027 物理 P3–P4
该表结构为"日期 | 版本 | 修改记录（多行项目符号）"。
- 默认提取把同一行的项目符号排在日期/版本**之前**，导致行归属错位；
- `sort=True` 则会把相邻列直接粘连（如 `…补充多处描述2026.04.30    V1.4.2`）。
- **处理**：修改日志必须走单元格网格提取 + 人工核对，它在差异对比阶段是重要参照（记录每次修订内容），不能作为普通段落处理。

### 6.7 【中】流程图节点文字被拉平 — 2026 物理 P70–P71、2027 物理 P68
"射击热量超限及冷却机制"流程图被提取为线性序列（`开始 / 检测到一发弹丸 / 弹丸类型为 / 17mm弹丸 / Q1 = Q1 + 10 / … / NO / YES / …`），**分支与连线关系全部丢失**。
- **处理**：流程图不参与自动差异比对；如需在报告里呈现，按图片引用并人工描述。

### 6.8 【中】公式上下标与排版语义丢失

- **处理**：比对时以**字符序列**为准，不依赖字号/基线；数值型结论（如 `Q2=Q0+100`）必须人工回看渲染页确认。

### 6.9 【低】笔记版 5 页内容流告警
MuPDF 在处理笔记版时报 `premature end of data in flate filter`（页 29、76、95、98、131）以及 `cannot find ExtGState resource 'GS'`（页 95）。官方版无任何告警。
- 这 5 页文本与渲染均可正常产出，但内容流经过 PDFium 重导出后存在轻微损坏。
- **处理**：不把笔记版作为正文来源，即可规避；仅当人工需要看这 5 页批注时，以官方版页面对照阅读。

## 8. 后续全文解析方案

### 8.1 推荐工具链
| 用途 | 工具 | 说明 |
|---|---|---|
| 文本 / 布局 / 书签 / 批注 | **PyMuPDF 1.28.x** | 主力；已验证可用 |
| 表格 | **PyMuPDF `find_tables()`** + 自写合并单元格归并 | pdfplumber 仅作交叉校验 |
| 书签 / 批注兜底 | pypdf 6.x | 与 PyMuPDF 结果互校 |
| 渲染核对 | PyMuPDF `get_pixmap()` + Pillow | 生成页面缩略图供人工比对 |
| 可选增强 | `pymupdf_layout` 包 | PyMuPDF 官方建议的布局分析增强，**先在 3–5 页试跑评估**再决定是否引入 |
| 明确不用 | OCR、LLM 补全、自研 PDF 解析器 | 本阶段已判定无扫描页，无 OCR 必要 |

### 8.2 建议处理流程
1. **校验前置**：对两份官方 PDF 重算 SHA256，与第 2 节比对，防止换版。
2. **章节骨架**：用内置书签建 `sections.json`（level / title / 物理页 / 印刷页），并用印刷目录做交叉校验；4 级子节只有书签有，需保留。
3. **按页归属**：把每一物理页切给一个章节；页眉页脚（`© 2026 大疆 版权所有` + 印刷页码）单独剥离，不进入正文。
4. **正文切割**：用 `get_text("dict")` 的 block/line/span 几何信息重建段落，**不要**用 `get_text("text")` 直接落盘（表格行会被拆散）。
5. **表格单独成块**：`find_tables()` → 合并单元格归并 → 输出 Markdown/JSON，附物理页锚点与表号（表 X-Y）。
6. **图片/流程图**：按 block 类型切出图片，流程图页记录"该页含流程图，语义未提取"，输出渲染图链接。
7. **规范化**：项目符号 U+F06C→`•`、U+F0D8→`◦`；合并空白；统一全半角（数字与英文）。
8. **产出**：`structured/2026.jsonl`、`structured/2027.jsonl`（每行一个 section/table，带 `physical_page`、`printed_page`、`section_no`、`type`），外加 `annotations.jsonl`（仅笔记版）与 `manifest.json`（含 SHA256 与工具版本）。
9. **抽样验收**：随机抽 20 页正文 + 全部抽样表格，与渲染图逐页人工比对后才算完成。
