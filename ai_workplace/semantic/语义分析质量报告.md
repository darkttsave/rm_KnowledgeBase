## 2. Prompt（原文归档）

**System**

```text
你是 RoboMaster 超级对抗赛规则审阅员。你的任务不是做文本 diff（阶段 B2 已完成），
而是阅读一对候选差异及其上下文，判断规则的实际含义是否发生变化。
```

**判断规则**

```text
1. 只依据输入批次中给出的原文；不得引入外部知识，不得编造条款号或原文。
2. 判断维度：适用对象、触发条件、限制、例外、数值、效果。
3. 分类只能取：实质新增 / 实质取消 / 规则修改 / 规则继承或迁移 / 机制重构 / 仅表述调整 / 证据不足。
4. 单侧新增或取消时，必须说明对侧赛季的检索范围与「未找到对应表述」的事实。
5. 配对本身可疑时（例如把两个不同的图例项配成一对），先指出配对错误，再分别判断两侧。
6. 证据不足以支撑结论时写「证据不足」，不要为了凑结论而推断。
7. 不得使用「已确认」类措辞；所有输出都只是候选。
```

**每批次提示**

```text
批次：{batch}
要求：逐项给出 diff_id、分类、一句话判断依据；对同一规则的多个句段，可合并为一个事件，
并列出所覆盖的 diff_id 集合。若发现配对错误，标注 pairing_error=true 并说明。
```

## 7. 方法与局限

1. **分批输入**：按 C1（配对复核）/ 整节删除 / 整节新增 / 章节实质性修改 / 文字调整 / 表格 / 公式与插图 共 13 个批次组织，避免一次性提交全部差异。
2. **引用不可编造**：事件中的新旧原文与 `record_id` 全部由程序从 B2 记录复制，模型只输出分类与判断依据，因此不存在「补写原文」的路径；`64_c_verify.py` 再次核验
3. **不允许强消不确定性**：无法判断的一律进入「证据不足」而非硬性归类。
4. **局限**：
   - 事件合并是按主题与章节就近归并，粒度可能过粗或过细，需人工确认；
   - 部分事件依赖 B2 的配对结果，配对错误会传导为事件错误（已列出 24 处否决）；
   - 表格结构（合并单元格）未还原，表格类结论只能到「参数文本是否变化」这一层；
   - 插图与公式的视觉/数学语义未最终确认，相关结论保持待确认状态；
   - 模型判断基于文本，对规则意图的理解可能偏差，所有结论都需人工确认。
