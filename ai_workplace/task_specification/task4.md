# 任务：RM 2026—2027 规则对比 · 阶段 B1 章节对齐

## 背景

阶段 A 全文结构化已通过验收。

现有两份官方规则的结构化 JSONL、Markdown 和章节骨架，均已完成生成及自动质量检查。

本次开始阶段 B1，目标是建立 2026 V2.2.0 与 2027 V1.0.0 之间的章节对应关系，为后续正文差异分析提供基础。

## 一、输入

直接复用阶段 A 已生成的：

- 2026 / 2027 章节骨架 JSON
- 2026 / 2027 结构化 JSONL
- 2026 / 2027 结构化 Markdown
- 两份官方 PDF
- 结构化质量报告与待人工核验清单

不重复执行 PDF 全文解析。

## 二、对齐原则

1. 以章节主题、标题、正文内容和上下级关系为依据，不得仅根据章节编号匹配。
2. 支持一对一、一对多、多对一，以及无法匹配的情况。
3. 区分：保留、重命名、迁移、合并、拆分、疑似新增、疑似删除。
4. 不得把“旧章节编号不存在”直接判定为规则删除。
5. 不得把“新章节标题第一次出现”直接判定为全新规则机制。
6. 优先通过程序生成候选对应关系，LLM 可以辅助判断语义，但需要保存判断依据。
7. 对不确定的对应关系标记待核验，不强制匹配。
8. 将 2027 手册第 1.2 节“新赛季主要变更”作为重要参考，但不能用其代替正文对齐。

## 三、输出要求

生成：

1. `章节对应关系.json`：机器可读的章节映射，保留新旧章节编号、名称、页码、对应关系、判断依据和待核验状态。
2. `章节对齐总览.md`：面向人工阅读的完整章节映射表。
3. `章节对齐异常清单.md`：无法匹配、可能存在合并拆分、新增删除等情况的章节。
4. `章节对齐质量报告.md`：说明覆盖情况、匹配方法与局限。

必须保证 2026 与 2027 的所有正式章节均在映射或待核验清单中出现，不允许静默遗漏。

## 四、暂不处理

- 不做逐条正文差异分析。
- 不对全部表格进行人工还原。
- 不处理完整的公式与流程图语义。
- 不建立 RAG 知识库。
- 不修改阶段 A 的原始结构化数据。
- 不开始最终变更总结。

完成后停止，等待审核，再决定是否进入 B2。
