# 任务：RM 规则阶段 A — 全文批量结构化

## 背景

《PDF预检查报告》和《结构化验证报告》已经完成。

结构化样本验证总体通过，现批准进入 2026 V2.2.0 与 2027 V1.0.0 两份官方规则的全文批量结构化。

本阶段目标是获得能够支持后续章节对齐、规则差异检测及原文追溯的两份结构化资产。

## 一、先核实章节路径问题

报告中的 `RMUC2026:1.2:p017:p003` 示例将 `1.2 关于比赛规则文件` 的路径写为：

`["阅读提示", "1.2 关于比赛规则文件"]`

请核实真实数据是否如此。

- 如果只是报告示例错误，修正报告即可。
- 如果是章节父子关系错误，修复章节骨架生成逻辑。
- 对全部章节增加父子路径一致性校验。

该项验证通过后再运行全文处理。

## 二、全文结构化

1. 复用现有 PyMuPDF 环境、章节骨架和样本提取逻辑，不重新开发 PDF 解析器。
2. 对两份官方规则全文进行结构化，按章节组织内容，不按物理页强行切章。
3. 沿用已经验证的 JSONL 数据结构，保留原始文本、规范化文本、页码、章节、文本坐标及原文来源。
4. 额外生成可阅读的 Markdown 视图，便于后续 AI 分析与人工检查。
5. Markdown 不作为事实主数据，不得因为展示格式限制而丢弃原文信息。

## 三、特殊内容处理

- 表格：保留原始网格、来源文本行及待核验标记，不猜测合并单元格。
- 公式：保留原文、上下标及分式布局信息，不自动修改数学表达式。
- 图片和流程图：保留位置及原图引用，不能正确提取语义时明确标记。
- 跨页段落：保持页码和文本来源追溯。
- 个人批注版：不作为官方规则正文来源。

## 四、自动质量检查

1. 对全文运行章节归属检查与记录完整性检查。
2. 检查重复、漏块、跨页、错误归属等问题。
3. 对原始文本与规范化文本进行字符保真检查。
4. 检查关键数字、单位、公式字符没有被改写。
5. 对表格执行原始文本覆盖检查，记录缺失和异常。
6. 生成需要人工核验的异常清单。
7. 重点抽查高风险表格、公式、图示及异常页面。

不要把“自动断言通过”等同于“全部规则语义已经人工确认”。

## 五、输出产物

在现有工作目录中生成：

- `2026_结构化.jsonl`
- `2027_结构化.jsonl`
- `2026_结构化.md`
- `2027_结构化.md`
- `结构化质量报告.md`
- `待人工核验清单.jsonl`

继续沿用已有工作区的目录组织与文件命名方式，保留原先全部预检查和样本验证结果。

## 六、任务边界

本次只完成阶段 A 的全文结构化，不开始跨赛季差异分析。

不建立 RAG 知识库，不引入多模型评测，不使用 LLM 猜测、修改或补全原文。

完成后停止，反馈质量报告及异常清单，等待审核。
