# 任务：RM 规则阶段 A — 结构化方案验证

## 背景

PDF 预检查已经完成，确认 RMUC 2026 V2.2.0 和 RMUC 2027 V1.0.0 两份官方规则具有完整文本层与可用的内置书签。

本次进入结构化处理验证阶段，但暂不进行全文差异比较。

## 工作要求

1. 复用现有 PyMuPDF 环境和预检查结果，不重复执行已经完成的环境探测。
2. 从两份 PDF 的内置书签提取完整章节骨架，保留四级章节结构、章节名称与对应页码。
3. 不得简单地将整个物理页归属于单一章节。需要结合文本块位置识别同页多章节和跨页章节。
4. 分别选取普通正文、复杂表格、公式及跨页章节进行小规模结构化试运行。
5. 表格优先使用 PyMuPDF；不能可靠恢复的合并单元格保留原始数据，标记待核验，不得根据空白单元格直接猜测内容。
6. 原始提取文本与规范化文本分别保存，规范化不得改变数值、单位、公式及条件表达。
7. 所有结构化内容必须保留来源文件、版本、章节编号、物理页码及必要的位置关联。
8. 个人批注版不得作为官方规则正文来源。

## 预期产物

- `2026_章节骨架.json`
- `2027_章节骨架.json`
- 小规模结构化样本（JSONL 或 Markdown）
- `结构化验证报告.md`

报告重点说明：

- 章节边界识别是否准确；
- 表格和公式是否存在数据丢失；
- 原始 PDF 与结构化文本能否相互追溯；
- 哪些内容需要人工核验；
- 是否能够安全进入全文批量结构化处理。

## 约束

- 原始 PDF 保持只读。
- 复用成熟工具，不重复造轮子。
- 不使用 LLM 编造或补全规则原文。
- 不开始 2026 与 2027 的规则差异分析。
- 不引入 RAG 或模型训练。
- 保留现有预检查产物，避免覆盖已有审核数据。

验证完成后停止，等待人工审核。
