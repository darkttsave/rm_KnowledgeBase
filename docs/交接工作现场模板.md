# 交接工作现场

> 适用角色：执行体  
> 重组来源：`Handoff_Protocol.md`、`Carry_Forward.md`、`STAGE_CHECKPOINT_TEMPLATE.md`

## 使用条件

项目或任务不变，但另一个执行体将接管同一个仓库或工作目录。重点是避免覆盖未提交修改、误判验证状态或破坏仍在运行的现场。

## 必须说明

- 当前工作目录、分支和 commit；
- 是否存在未提交修改，正在修改哪些文件；
- 是否存在仍在运行的进程、测试或设备连接；
- 当前任务停在哪里；
- GitHub、调参手册或任务日志入口；
- 尚未进入 Git 或日志的重要本地状态；
- 下一执行体能否立即接管，以及接管后的第一步。

两个执行体不得在没有明确文件边界的情况下同时修改同一工作目录。接管状态不明确时，新执行体先只读检查。

## 模板

```markdown
# 工作现场交接

## Workspace
- Path：
- Branch：
- Commit：
- Dirty Files：
- Running Processes / Connections：

## Current Task

## Current Position

## Existing Evidence
- GitHub / Git：
- Tuning Manual / Task Log：

## Important Local State
只写尚未进入 Git 或日志的内容。

## First Next Action

## Takeover Status
READY / WAIT / PARTIAL
```

## 最短交接

如果修改已经提交、工作区干净、日志已经更新且没有后台进程，可缩短为：

```text
接管仓库与分支：<repo / branch>，当前 commit：<sha>。
测试记录：<调参手册或任务日志路径>。
工作区干净，无后台进程。
下一步：<明确动作>。
```

完整交接建议控制在 `300～700` 个中文字符；已有材料能回答的内容只提供路径。
